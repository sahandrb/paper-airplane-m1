------------------------------------------------------------------------------------------
1. PURPOSE
------------------------------------------------------------------------------------------
A 2D, side-view engineering "Paper Airplane Flight Lab" that reproduces
Stengel Flight Dynamics (2005) Example 1.3-1 (the same MATLAB the professor
issued) and then lets the user explore the same point-mass model interactively.

It is NOT a game: no score, no points, no crash explosions, no sound required.

What it teaches, visually:
  - Equilibrium glide at (L/D)max (case a): a straight path at constant V and gamma.
  - The phugoid mode (cases b, c): kinetic and potential energy trade places
    at nearly constant angle of attack.
  - Why a fast throw (case d, 3 V*) loops: lift scales with V^2.
  - The difference between Reference integration (tf = 6 s, altitude may go
    negative — that is what the professor's code does) and Physical flight
    (stop at h = 0).
  - That this model is a point mass: the nose follows the path with a fixed
    alpha, there is no pitch inertia, and two identical launches produce
    identical trajectories.

The homework MATLAB is Example 1.3-1 / PaperPlane.m (Stengel). Four cases,
ode23, tf = 6 s, no ground event.

3. SCENARIO WALKTHROUGH (WHAT THE USER EXPERIENCES)

3.1 Home screen / pre-launch
    The window opens on a dusk field (Section 7). A rubber-band catapult sits
    on the ground. The paper dart rests on the ramp. The top of the ramp —
    the launch point — is at the professor's initial height H = 2 m, range
    r = 0.

    The user changes launch speed V0 and flight-path angle gamma0 with
    sliders and keyboard, LIVE, before anything is integrated:
      - The ramp rotates to gamma0 about its hinge on the pillar
        (the pillar stays upright).
      - The airplane sprite rotates to
            theta0 = alpha_star + gamma0
        so the nose sits alpha_star (~9.77 deg) above the ramp. This is
        intentional and pedagogical: the ramp is the velocity direction
        (gamma); the body is at theta; the wedge between them is alpha.
      - A short arc between the ramp and the fuselage is labelled
        "alpha = 9.77 deg" (live value of alpha_star, which is constant).
      - A dashed predicted-trajectory preview updates in real time: the
        same solver as a real launch, from the current (V0, gamma0, h=2, r=0),
        using the current mode's termination (Reference: 6 s, no ground stop;
        Physical / Monte Carlo preview: terminal event h = 0, direction -1).
      - Numeric readouts: V0 (m/s and as a multiple of V*), gamma0 (deg),
        theta0 (deg), alpha_star (deg), and — in Physical mode — the
        predicted landing range and flight time.

    Preset buttons (also keys 1-4):
      A  Equilibrium glide     V0 = V*,      gamma0 = gamma*
      B  Horizontal, V*        V0 = V*,      gamma0 = 0
      C  Horizontal, 1.5 V*    V0 = 1.5 V*,  gamma0 = 0
      D  Horizontal, 3 V*      V0 = 3 V*,    gamma0 = 0
    Pressing a preset snaps the sliders, ramp, sprite, and preview.

    Slider ranges (CONFIG, justified in Section 7.2):
      V0     = 1.0 .. 12.0 m/s     step 0.05 m/s   default V*
      gamma0 = -40 .. +50 deg      step 0.5 deg    default gamma*
    1.0 m/s is a limp toss (the airplane still has CL so it does not
    free-fall like a stone). 12.0 m/s is just above 3 V* = 10.648 m/s so
    case D is not parked on the end stop. Angles cover a downward throw,
    the equilibrium glide (−10.28 deg), a level toss, and a lofted toss.
    A caution banner appears when V0 > 5 m/s:
      "Stengel notes that a real paper wing may buckle above ~5 m/s.
       Case d (3 V* ≈ 10.65 m/s) is a numerical demonstration."
    Source of the 5 m/s remark: Stengel's Paper Airplane Simulation page
    (Section 14). This is a documentation warning, not a model change.

    Two buttons are always visible on the home/pre-launch screen:

      RESET
        - Clears ALL stored trails and the trail legend.
        - Returns the airplane to the launcher at the current sliders
          (or the last used V0, gamma0 — do not wipe the sliders).
        - Resets the camera to the pre-launch framing (Section 7.2).
        - Clears any finished-run result numbers from the HUD.
        Use this to start a clean session.

      RESTART
        - Returns the airplane to the launcher (pre-launch pose, same
          sliders) and resets the camera to the pre-launch framing.
        - Does NOT clear trails or legend entries.
        - The next Launch will draw a NEW trail in the next colour and
          add a new legend row (V0, gamma0, and the range once known).
        Use this to overlay several flights, including cases A-D.

    After a run has finished, both buttons remain available (the finished
    airplane can freeze at its last point or snap back only when the user
    presses RESET or RESTART). A separate LAUNCH control (Space / button)
    starts a new integration from the current sliders.

    Additional pre-launch controls: mode selector (Reference, Physical,
    Phugoid, Monte Carlo, Heatmap), playback-speed setting that will apply
    after launch (0.25× / 1× / 4×), and in Monte Carlo mode the N / sigma
    sliders (Section 3.4).

3.2 Flight
    On Launch the full trajectory is PRECOMPUTED with solve_ivp (Section 6)
    and then played back locked to simulation time:
        t_sim += speed_factor * dt_wall
    The user does not change V0 or gamma0 during a run (those are initial
    conditions). Playback speed 0.25× / 1× / 4× can be changed while the
    clip plays.

    What is drawn:
      - The airplane sprite at the interpolated (r(t), h(t)), rotated by
        the instantaneous theta(t) = alpha_star + gamma(t). No lag.
      - A persistent coloured trail of that run, stored in WORLD
        coordinates (r, h) like the Cessna project. The trail stays after
        the run ends. Previous runs' trails stay unless RESET was pressed.
      - Live telemetry panel (Section 7.6).
      - In Reference mode, the portion of a trail with h < 0 is drawn
        dashed, over a hatched "below ground" band, with a note:
        "Reference mode: integration continues below h = 0
         (professor / Stengel, tf = 6 s)."
      - In Physical mode the run stops at the ground event; the HUD
        reports flight time and landing range.

    When t_sim reaches the final sample the view freezes on the last state
    (or the landing point) and the results strip appears: flight time,
    range (see definition in 3.3), min/max V and gamma, plus
    Show plots / Export / RESET / RESTART.

3.3 Results, range definition, trail legend

3.4 Modes
    REFERENCE
      Integrates each launch to tf = 6 s with NO ground event, matching
      the professor. Altitude may become negative (case a ends at
      h ≈ −1.801 m). A-D presets reproduce Figure 1 and Figure 2.
      A button "Drop A–D trails" computes all four Reference trajectories
      and adds four coloured trails + legend rows without the user having
      to fly each one (useful before defending the plots). Playback of a
      single launch still uses the chosen preset or sliders.

    PHYSICAL
      Same equations, but solve_ivp is given a terminal event
          h_event(t, x) = x[2]            # altitude
          h_event.terminal  = True
          h_event.direction = -1          # downward crossing only
      Reports landing range and flight time. Expected values for A-D
      are in Section 12. Does not produce negative h (except a numerical
      1e-16-level overshoot at the event, which you must display as 0).

    PHUGOID
      One launch (current sliders) in either Reference timing (default,
      tf = 6 s) so the linear vs nonlinear comparison is visible for
      several periods. After (or during) playback:
        - The nonlinear path is the solid trail.
        - The linearized (V, gamma) solution about (V*, gamma*), converted
          to (r, h) by the hybrid kinematics of Section 4.9, is drawn as
          a contrasting dashed overlay.
        - A live energy plot (KE, PE, total) is shown (bottom strip or
          results figure). Total energy must fall; the drop equals the
          work of drag (Section 4.8).
        - Eigenvalues, period, and damping of the 2×2 Jacobian are shown,
          computed in code, not hard-coded. Expected numbers: Section 4.9.
        - If the perturbation is large (|δV|/V* > 0.3 or |δgamma| > 15 deg)
          show: "Linear model is outside its small-perturbation region."
          Case d must trigger this; the overlay will not loop (the linear
          model cannot). That disagreement is the lesson.

    MONTE CARLO
      Still the Physical point-mass model. The user sets V0, gamma0 as
      the mean throw, then:
          N        CONFIG default 50, range 10..200
          sigma_V  default 0.20 m/s     ASSUMPTION (hand-speed jitter)
          sigma_gamma default 3.0 deg   ASSUMPTION (hand-angle jitter)
      These sigmas are NOT from Stengel and NOT from a measured data set.
      Label them "Assumption: illustrative hand-throw scatter".
      Each sample: V0' ~ Normal(V0, sigma_V^2), gamma0' ~ Normal(gamma0,
      sigma_gamma^2), independent, then Physical integration.
      Draw N faint trails plus a landing-point histogram (or rug) on the
      ground. Report mean and std of landing range, and the count of
      samples that hit the V→0 guard before landing (if any).
      Do not add one legend row per sample (that would be unreadable);
      add a single summary row, e.g. "MC N=50  V0=… ± …  γ0=… ± …  r=… ± …".

    HEATMAP
      A results-style view (can replace the world view after a short
      progress bar). Grid of Physical landings over the slider rectangle:
          V0     linspace(1.0, 12.0, CONFIG nV=41)
          gamma0 linspace(-40 deg, +50 deg, CONFIG nG=31)
      Colour = landing range r_f. Mark cases A-D and the (V*, gamma*)
      point. A computed maximum on this grid is expected near
      r ≈ 16.00 m at about V0 ≈ 9.4 m/s, gamma0 ≈ −8 deg
      (this spec's own RK23 survey, Section 7.2). Do not hard-code the
      peak as a physical constant; compute it and allow a few-percent
      tolerance in tests against that ballpark.
      Recompute on a button; cache the last grid in memory.

    Overlaying launches (the "Compare" capability) is not a sixth physics

4.1 Notation and units

4.2 Constants — from the professor's MATLAB (paper_airplane_readable.txt)

    the homework pi with a different value in the coefficient formulas.

      S    = 0.017          # reference area            [m^2]
      AR   = 0.86           # wing aspect ratio         [-]
      e    = 0.9            # Oswald efficiency         [-]
      m    = 0.003          # mass                      [kg]
      g    = 9.8            # gravity                   [m/s^2]
      rho  = 1.225          # sea-level air density     [kg/m^3]
      CD0  = 0.02           # zero-lift drag CDo        [-]
      H0   = 2.0            # initial height            [m]
      R0   = 0.0            # initial range             [m]
      TF   = 6.0            # Reference final time      [s]

    The MATLAB file multiplies by the literal 3.141592 (not MATLAB's pi)
    in CLa and epsilon:
      PI_HOMEWORK = 3.141592
    Use that named constant for CLa and epsilon so the validation table
    matches numerical_checks.txt bit-for-bit at 1e-12 relative level.

    Note (document in docs/theory.md, do not "fix"):
      numpy.pi = 3.141592653589793 differs from 3.141592 by 6.54e-7.
      That changes CLa by about 2.69e-7 /rad and epsilon by about

4.3 Derived geometry (not used in the EOM; used for display and Re note)
    From the definitions AR = b^2 / S and S = b * c_mean:

      b      = sqrt(AR * S) = 0.120913192001535 m     (12.09 cm)
      c_mean = S / b        = 0.140596734885506 m     (14.06 cm)

    Computed in this spec from the homework S and AR. The point-mass
    equations never need b or c. Reynolds number at V*, using
    nu_air ≈ 1.4607e-5 m^2/s (ISA 15 °C, a standard value — say so):
      Re = V* * c_mean / nu ≈ 3.42e4
    With the rounder nu = 1.5e-5 m^2/s: Re ≈ 3.33e4.
    This belongs in docs/theory.md as context (low-Re limitation).

4.4 Aerodynamic coefficients (computed once; CONSTANT during flight)

    Helmbold / finite-wing lift slope (MATLAB line 11):

      CLa = PI_HOMEWORK * AR / (1 + sqrt(1 + (AR/2)**2))
          = 1.29362167202453   [1/rad]

    This is algebraically identical to the uncompressed DATCOM form
      CLa = 2 * PI * AR / (2 + sqrt(AR**2 + 4))
    (same PI). Do not use the 2*pi infinite-wing slope: that would give
    alpha* ≈ 2 deg instead of 9.77 deg.

    Induced-drag factor (MATLAB line 13):

      epsilon = 1 / (PI_HOMEWORK * e * AR)
              = 0.411253168483586

    Drag polar:  CD = CD0 + epsilon * CL**2

    (L/D)max: maximise CL / (CD0 + epsilon CL^2). Setting the derivative
    to zero gives CD0 = epsilon * CL^2, so

      CL_star = sqrt(CD0 / epsilon)     = 0.220526289045093
      CD_star = CD0 + epsilon*CL_star**2 = 0.04     exactly 2*CD0
      LD_max  = CL_star / CD_star        = 5.51315722612733

    CD is exactly 0.04 because at (L/D)max the induced drag equals CD0.
    Numerical source for all of the above: recomputed in this spec from
    the MATLAB formulas with PI_HOMEWORK; agrees with numerical_checks.txt.

    Angle of attack (MATLAB line 19), CONSTANT because CL is locked:

      alpha_star = CL_star / CLa
                 = 0.170472011882708 rad
                 = 9.76732680598316 deg

4.5 Equilibrium glide (MATLAB lines 17-18)

    Set Vdot = 0 and gammadot = 0 in Section 4.6. Dividing the two force
    balances gives tan(gamma) = -CD/CL, hence

      gamma_star = -atan(1 / LD_max)
                 = -0.179433441298775 rad
                 = -10.2807788899282 deg

    Vertical force balance (lift and drag both have an upward component
    in a descent) is what the professor coded:

      V_star = sqrt( 2*m*g / (rho * S * (CL*cos(gamma) - CD*sin(gamma))) )
             = 3.54937084251753 m/s

    at gamma = gamma_star, CL = CL_star, CD = CD_star.

    Equivalence (prove in docs/theory.md and test numerically):
      From tan(gamma) = -CD/CL  =>  CD = -CL * tan(gamma).
      Then CL cos(gamma) - CD sin(gamma) = CL / cos(gamma),
      so V_star = sqrt( 2*m*g * cos(gamma) / (rho * S * CL) )
      which is the familiar L = m g cos(gamma) form.
    This spec verified the two expressions agree to 4e-16 m/s.
    Also verified at equilibrium:
      L = CL * q * S = m g cos(gamma*) = 0.0289279819899311 N
      D = CD * q * S = -m g sin(gamma*) = 0.00524708090181773 N
      W = m g = 0.0294 N
      L cos(gamma*) - D sin(gamma*) = W   (vertical balance)

    1.5 V* = 5.3240562637763 m/s
    3   V* = 10.6481125275526 m/s

    Pitch at equilibrium: theta* = alpha* + gamma* = -0.513452 deg
    (the nose is slightly below the horizon while the path is −10.28 deg).

    Case a identity, useful as a test: a Physical landing from (V*, gamma*,
    h=H0) is a straight line, so
      r_land = H0 * LD_max = 11.0263144522547 m
      t_land = -H0 / (V* * sin(gamma*)) = 3.15724430361001 s
    (this spec; matches the event-detected values in Section 12).

4.6 Equations of motion (MATLAB EqMotion, lines 53-62)
    q_dyn = 0.5 * rho * V**2

      Vdot     = (-CD * q_dyn * S - m * g * sin(gamma)) / m
      gammadot = ( CL * q_dyn * S - m * g * cos(gamma)) / (m * V)
      hdot     = V * sin(gamma)
      rdot     = V * cos(gamma)

    Same signs as the professor. Same signs as the Cessna project's glide
    equations (the paper airplane simply has constant CL, CD and no
    thrust). State: x = [V, gamma, h, r].

    V → 0 guard: gammadot divides by V. In dynamics.rhs, if
    V < CONFIG V_EPS (1e-9), do not divide; raise a clear error or return
    a finite dummy — simulation.py must never feed V <= 0 to the RHS.
    Integration stops if V < CONFIG V_MIN_STOP = 0.05 m/s, with status
    "speed collapsed (V → 0); gammadot is singular". A survey of the
    recommended slider box saw V as low as ~0.012 m/s on some lofted
    throws, so the guard is necessary. Reference cases A-D stay above
    2.099 m/s (case d minimum; numerical_checks.txt).

4.7 The three angles
      gamma  = angle of the velocity vector above the horizon
      theta  = angle of the body (dart centreline) above the horizon
      alpha  = theta - gamma   (= alpha_star, constant, ~9.77 deg)
      hence  theta(t) = alpha_star + gamma(t)

    The sprite is rotated by theta(t), not by gamma(t). The velocity
    vector / preview-tangent / ramp is at gamma. Drawing theta = gamma
    would hide angle of attack and is wrong.

    This rotation is KINEMATIC, not DYNAMIC: there is no pitch rate q
    and no moment equation. Document that in the HUD (small grey line
    "point-mass: alpha fixed, no pitch inertia") and in docs/theory.md.
    Stengel himself notes that angular dynamics are omitted and matter
    especially for the loop.

4.8 Mechanical energy
      KE = 0.5 * m * V**2
      PE = m * g * h            # datum h = 0 (the ground plane)
      E  = KE + PE

    Lift is perpendicular to V and does no work. Drag dissipates energy:
      dE/dt = - D * V
    so  E(t) - E(0) = - ∫ D V dt.
    This spec checked case a over 0..6 s:
      E(0) = 7.7697050067e-02 J
      E(6) = -3.4045965701e-02 J     # negative PE because h(6) < 0
      ΔE   = -1.1174301577e-01 J
      ∫ D V dt = 1.1174301577e-01 J
      residual |ΔE + ∫DV dt| ≈ 1.6e-13 J
    Test this. The live energy plot must show KE and PE exchanging (the
    phugoid) while E declines monotonically (drag). In Reference mode PE
    may become negative; that is consistent with the h < 0 datum.

4.9 Linearized phugoid (derived and numerically verified in this spec)
    Density is constant, so (h, r) do not feed back into (V, gamma).
    Linearize the (V, gamma) subsystem about x* = (V*, gamma*).

    Write
      f_V = -k_D V^2 - g sin(gamma),     k_D = CD * rho * S / (2 m)
      f_G =  k_L V   - (g / V) cos(gamma), k_L = CL * rho * S / (2 m)

    Jacobian J = [[∂f_V/∂V, ∂f_V/∂gamma],
                  [∂f_G/∂V, ∂f_G/∂gamma]]:

      ∂f_V/∂V     = -CD * rho * V * S / m
      ∂f_V/∂gamma = -g * cos(gamma)
      ∂f_G/∂V     =  CL * rho * S / (2 m) + g * cos(gamma) / V**2
      ∂f_G/∂gamma =  g * sin(gamma) / V

    Evaluated at (V*, gamma*), with the homework constants (this spec,
    verified against a centred finite-difference Jacobian to ~1e-8):

      J = [[ -0.985541970605702 , -9.64266066331038  ],
           [  1.53081998978802  , -0.492770985302851 ]]

    Eigenvalues (numpy.linalg.eigvals, this spec):

      lambda = -0.739156477954277 ± 3.83411944090805 j

    Hence
      sigma = -0.739156477954277   1/s
      omega =  3.83411944090805    rad/s
      T_lin = 2 π / omega          = 1.63875575709543 s
      wn    = sqrt(sigma^2+omega^2)= 3.90471819547209 rad/s
      zeta  = -sigma / wn          = 0.18929829015866
      amplitude ratio per period   = exp(sigma * T_lin) = 0.297810788027281

    Checks: trace(J) = 2 sigma, det(J) = wn^2 (verified).
    f(V*, gamma*) = 0 to ~1e-16 (verified).

    Closed form: δx(t) = expm(J t) @ δx0,   δx0 = [V0 - V*, gamma0 - gamma*].
    Use scipy.linalg.expm (or the real 2×2 form with e^{σt}[cos ωt I +
    sin(ωt) (J - σ I)/ω]). Then V_lin = V* + δV, gamma_lin = gamma* + δγ.

    Hybrid kinematics (USE THIS for the overlay path):
      integrate hdot = V_lin sin(gamma_lin), rdot = V_lin cos(gamma_lin)
      from (h, r) = (H0, 0). This keeps the linear dynamics and the exact
      geometry of the path.
    Fully linearized kinematics (optional, docs only):
      hdot ≈ V* sin γ* + sin(γ*) δV + V* cos(γ*) δγ
      rdot ≈ V* cos γ* + cos(γ*) δV - V* sin(γ*) δγ

    This spec compared hybrid linear vs nonlinear over 6 s:
      case a: max errors ≈ 0 (they share the equilibrium)
      case b (δγ0 = +10.28 deg, δV = 0):
          max |ΔV| = 0.012 m/s, |Δγ| = 0.48 deg, |Δh| = 0.0075 m
          (the linear model is excellent here)
      case c (δV = 1.775 m/s):
          max |ΔV| = 0.204 m/s, |Δγ| = 7.20 deg, |Δh| = 0.107 m
      case d (δV = 7.099 m/s):
          max |Δγ| ≈ 410 deg — the linear model does NOT loop.
    Nonlinear V-peak spacing (this spec, RK23):
      case b periods 1.641 s, 1.639 s (mean 1.640 s)
      case c periods 1.645 s, 1.641 s (mean 1.643 s)
    These confirm T_lin = 1.639 s.

4.10 Lanchester approximation (docs and Phugoid panel, as a comparison)
    Classical constant-alpha, small-disturbance, drag-free period, and
    the powered-level-flight damping estimate (MIT Unified Engineering):

      T_Lanch = π * sqrt(2) * V* / g = 1.60912644463448 s
      zeta_Lanch = 1 / (sqrt(2) * LD_max) = 0.128258047464256

    T_Lanch is within ~2 % of T_lin and of the nonlinear peak spacing.
    zeta_Lanch under-predicts damping (0.128 vs 0.189) because the
    airplane is in a glide, not level powered flight; say so on the panel.

    Book / webpage rounding (NOT a bug — document it):
      Stengel's prose quotes rounded figures α ≈ 9.3°, L/D ≈ 5.2,
      V ≈ 3.7 m/s, period ≈ 1.7 s. The MATLAB (and this project) give
      α* = 9.767°, L/D = 5.513, V* = 3.549 m/s, T_lin = 1.639 s.
      Using V = 3.7 m/s in Lanchester's formula yields T = 1.677 s,
      which is the "about 1.7 s" in the book. If a professor asks about
      1.7 s, that is the source.

4.11 Why case d loops
    q_dyn scales as V^2, so at 3 V* the dynamic pressure (and the lift,
    CL being fixed) is 9 times the equilibrium lift. gammadot is large
    and positive. In the integration, gamma reaches π (inverted) at
    t ≈ 0.595 s (r ≈ 0.71 m, h ≈ 4.423 m, V ≈ 3.19 m/s) and 2π
    (upright after one loop) at t ≈ 1.432 s (r ≈ 1.89 m, h ≈ 1.85 m,
    V ≈ 5.52 m/s). Maximum gamma ≈ 6.7835 rad ≈ 388.7 deg
    (numerical_checks.txt: 6.783534181827585). After the loop, drag
    bleeds the extra energy and the motion decays toward (V*, gamma*).

5. ASSUMPTIONS AND LIMITATIONS (put in README, docs/theory.md, and a HUD line)
------------------------------------------------------------------------------------------
  1. Point mass in the vertical plane. No lateral motion, no roll, no yaw.
  2. Angle of attack is locked at alpha_star. There is no short-period mode,
     no pitch inertia, and no stall. The drawn pitch is kinematic:
     theta = alpha_star + gamma.
  3. CL and CD are constant (the (L/D)max point). They do not vary with
     alpha, Reynolds number, or time.
  4. Atmosphere is constant rho = 1.225 kg/m^3. No wind.
  5. The professor's Reference integration has no ground event: h may go
     negative. That is deliberate reproduction, not a bug. Physical mode
     stops at h = 0.
  6. Two launches with identical (V0, gamma0) produce identical trajectories
     (the ODE is deterministic). Real paper airplanes scatter because the
     hand cannot repeat theta0 and q0 and because low-Re flow is unsteady.
     Monte Carlo scatter on (V0, gamma0) is an ASSUMPTION that illustrates
     this, not a measured dataset.
  7. The dart sprite is larger than the true mean chord (Section 7.2).
     Label "SPRITE NOT TO SCALE ×N". The scale bar is the length reference.
  8. Low Reynolds number (Re ~ 3.4e4 at V*). CD0 = 0.02 may be optimistic.
     Document, do not "correct" it.
  9. Stengel notes that a real paper wing may buckle above ~5 m/s. Case d
     at 3 V* ≈ 10.65 m/s is a numerical demonstration of the equations.
 10. Rigid-body parameters (Iy, Cm, a pitching-moment arm) are NOT in the
     homework. Do not invent them. See Section 17.

6. NUMERICAL METHOD
------------------------------------------------------------------------------------------
  - Integrator: scipy.integrate.solve_ivp, method="RK23"
    (Bogacki–Shampine 2(3) pair; SciPy documents this as the counterpart
    of MATLAB ode23, which the professor used).
  - Reference validation runs (must match Section 12):
        rtol = 1e-8, atol = 1e-10, dense_output = True
        do NOT set max_step (leave the default) so results line up with
        numerical_checks.txt / the render.py that produced it.
  - Interactive playback: PRECOMPUTE the whole trajectory at Launch with
    the settings above (Physical adds the h = 0 terminal event), then
    interpolate with sol.sol(t) or an equivalent dense sample (~200 Hz
    stored table). Do not re-integrate every frame.
    Playback: t_sim += CONFIG speed_factor * dt_wall, clamped to [0, t_final].
  - Preview (pre-launch, every slider change): the same solver. Cheap
    enough to recompute live; debounce only if a frame budget requires it.
  - Heatmap / Monte Carlo: rtol=1e-6, atol=1e-8, max_step=0.05 is allowed
    for speed. Physical event still required.
  - float64 everywhere in physics.
  - Event h = 0, direction = -1, terminal = True in Physical mode.
  - V guard: Section 4.6.
  - Time array for exported Figure 2: np.linspace(0, 6, 2401) is fine
    (0.0025 s spacing; matches the reference render.py sampling).
